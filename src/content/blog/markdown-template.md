## 0. Frontmatter 必填项

每篇文章开头必须有：

```yaml
---
title: 文章标题
description: 一句话摘要，会出现在列表页
pubDate: 2026-09-12
category: 前端
tags:
  - 关键词A
  - 关键词B
---
```

说明：

- `category`：主分类，**一篇只能一个**（如 `前端` / `后端` / `模板`）
- `tags`：细粒度标签，可多个
- 可选：`updatedDate`、`draft: true`（草稿不发布）

## 5. 代码块

短命令：

```bash
npm run dev
npm run build
```

带语言的代码（便于高亮）：

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };

function unwrap<T>(result: Result<T>): T {
  if (!result.ok) {
    throw new Error(result.error);
  }
  return result.value;
}
```

```json
{
  "name": "mayimama-blog",
  "private": true
}
```

提示：围栏代码用三个反引号，并写上语言名（`ts` / `bash` / `json` 等）。

## 6. 表格

| 场景 | 建议写法 | 不建议 |
| --- | --- | --- |
| 报错信息 | 原样贴进代码块 | 只说「报错了」 |
| 配置项 | 表格或列表对照 | 大段口语描述 |
| 对比方案 | 表格列优劣 | 只有形容词 |

对齐示例：

| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 文本 | 数值 | 100 |
| 更长一点的说明 | 42 | 3.14 |

## 推荐正文结构（可删改）

### 背景

用 2～4 句话说明：在什么项目 / 什么场景下遇到问题。

### 现象

- 具体报错或异常行为
- 影响范围（本地 / CI / 生产）

### 排查过程

1. 第一步做了什么，看到了什么
2. 排除了哪些方向
3. 最终卡在哪一点

### 解决方案

把可执行的步骤写清楚，关键配置用代码块给出。

### 结论与沉淀

- 一句话结论
- 可复用的检查清单
- 仍未解决的问题（如果有）

## 9. 其他常用写法

脚注式补充（用括号或引用代替也行）：

有些细节不影响主线，可以放在引用或列表末尾，避免正文太碎。
